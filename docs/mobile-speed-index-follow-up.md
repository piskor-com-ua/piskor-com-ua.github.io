# Наступний етап оптимізації мобільного каталогу

Дата: 18.10.2026. База — актуальний main `4518110e9bf1cd34ec4ec192238122d11c416ad6`. Попередній [production PSI](https://pagespeed.web.dev/analysis/https-piskor-com-ua-portfolio/bcavzppca4?form_factor=mobile) мав mobile Speed Index 3,602 с, FCP 0,972 с і LCP 1,222 с. Ціль ≤1 с потребує нового production вимірювання після релізу; локальний результат її не підтверджує.

## Зміни доставки

- Мобільні картки до 700 px використовують AVIF через нативний picture/source. Ті самі вихідні кадри, пропорції, розміри, sizes та пріоритети; запасний img із WebP збережений. Desktop і браузери без AVIF використовують попередні WebP. Галереї та оригінальні файли не змінені.
- AVIF quality=60, speed=6, max_threads=2; усі варіанти генеруються з вихідної обкладинки, без повторного стиснення зменшеного WebP. Для 46 обкладинок шириною 640 px: 1 866 336 → 1 098 737 B, економія 41,1%. Кожна з цих AVIF-версій менша за відповідний WebP; діапазон економії 26,2–47,5%.
- Обидва використовувані накреслення WOFF2 й inline CSS оголошуються перед великим SEO/JSON-LD блоком. Regular більше не чекає першого обчислення стилів для початку запиту. Шрифти залишаються окремими кешованими ресурсами; їхні байти та дизайн не змінюються.
- Оптимізатор, fingerprinting, allowlist і перевірки розмірів підтримують AVIF у source/srcset. Браузерна перевірка очікує завершення асинхронного перемикання picture після resize та перевіряє AVIF на 390 px і WebP на 1440 px обома мовами.

## Парне локальне порівняння

Lighthouse 13.5.0, Chrome 155, стандартні mobile/desktop preset, gzip через scripts/serve-benchmark.py. Холодні окремі сесії, банер першого візиту, без збереженої згоди. Main і зміни чергуються. Перед запуском перевірено відповідність HTML двох серверів двом артефактам. Лабораторні URL без production CDN/HTTPS не є PSI чи CrUX.

## Приймання та публікація

Збірка перевіряє 113 HTML, 46 двомовних кейсів і 184 адаптивні картки; браузерна матриця — 92 сторінки кейсів × 390/768/1440 px. Окремо перевіряються UA/EN-каталоги, вибір формату, галерея та фокус, контакти, мовні переходи й стани аналітики. Для публікації потрібні успішні CI і Pages, перевірка live AVIF/WebP, noindex, discovery та новий мобільний PSI.

Cloudflare до мерджу не змінюється. Після успішного Pages deployment потрібно перевірити, що чинний місячний TTL для версіонованої статики охоплює також `.avif`, а query string `v` входить у cache key. HTML і discovery мають зберігати короткий TTL. Окремий післямерджевий крок — перевірити короткий edge-кеш GET без query string лише для `/portfolio/` і `/en/portfolio/`, з повагою до origin max-age=600 та browser TTL origin. Потрібні цільовий purge цих двох URL після кожного deployment, новий HTML, перевірка MISS/HIT і порівняння TTFB. Решта HTML, discovery й дані не входять у це правило; загальний Cache Everything не потрібен.

Контент, видимий банер, згода на GA4, noindex та три інструменти WebMCP зберігаються. Agentic Browsing перевіряється на реальному домені після публікації, бо локальний HTTP не підтверджує дію production Origin Trial.

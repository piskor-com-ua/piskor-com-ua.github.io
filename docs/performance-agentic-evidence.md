Для повторення встановити npm ci і запустити node scripts/benchmark-lighthouse.cjs BASELINE_URL CANDIDATE_URL. Звіти та summary.json зберігаються в output/lighthouse. Поточний запуск використовував локальні порти 4184 і 4183.

## Перевірка у Linux Chromium

CI додатково виявив переповнення мобільної шапки на 1 px: група UA/EN закінчувалася на x=391 при viewport 390. Виправлено проміжки спільної мобільної шапки та стискання логотипа в доступній ширині; критерій переповнення не послаблено. Посилання навігації отримали висоту натискання 44 px. Перевірки після resize очікують готовності шрифтів і двох кадрів компонування; за помилки CI зберігає геометрію й знімок.

## Межі приймання

Native WebMCP перевірений у сумісному локальному браузері. Це не означає загальну підтримку API всіма production-браузерами чи активний origin trial домену. Без API адаптер не робить запитів каталогу.

CI додатково повторює всю матрицю та перевіряє двомовну галерею, повернення фокуса, контакти, перемикання мови й стани GA4 без вибору/відмови/згоди/відкликання через мережевий stub. Він не підтверджує поведінку Cloudflare beacon на живому домені.

Після мерджу потрібні Pages deployment, перевірка live-ресурсів та окреме застосування/перевірка Cloudflare Cache Rules за [порядком підтримки](performance-agentic-maintenance.md). Річний immutable не підготовлений як безумовно безпечна політика: стабільні шляхи з v не є архівом історичних байтів. Індексація залишається вимкненою.

## Закриття критичних Image Delivery рекомендацій

Дата: 20 жовтня 2026 року. Кодова база — актуальний на початок роботи `main`, commit `cac6aa18652151aad8067b81cb3219a948c6c676`; PSI-початкові дані — Lighthouse 13.5.0, mobile, viewport 412×823, DPR 1.75. На 22 погоджених маршрутах початкові звіти мали 39 вузлів Image Delivery. Повторний локальний Lighthouse після профілювання показав ще один завантажений lazy-gallery кадр, якого не було в першій вибірці. У маніфесті збірки тепер 40 вузлів і 34 унікальні ресурси з розрізненням ролі зображення та старих/поточних URL.

Збірка додає кандидат, розмір якого відповідає фактичній ширині мобільного слота й DPR. Стиснення знижується лише коли це потрібно для усунення оцінених PSI-заощаджень; усі 40 ресурсів мають пройти перевірку меж Lighthouse, інакше збірка завершується помилкою. Локальний повторний Lighthouse на всіх 22 маршрутах: **0 знахідок Image Delivery, 0 B оцінених заощаджень**. Додатково візуально порівняно п’ять кадрів із найнижчими вибраними quality-профілями у фактичному мобільному CSS-розмірі — композиція й помітна деталізація збережені.

Перевірки збірки: 188 Python-тестів; браузерна матриця — 276 перевірок; 7 410 геометричних перевірок на 108 сторінках без помилок; 10 WebMCP-тестів і схема/discovery-перевірка успішні. **Це локальна діагностика, не production PSI або CrUX.** Після merge і Pages deployment повторити публічний PSI для погоджених маршрутів, зберегти Image Delivery details і виміряти FCP/LCP/SI; до цього production-критерій не вважати закритим.

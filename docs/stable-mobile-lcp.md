# Мобільний LCP: рендеринг довгого каталогу

База — `main` 4bbbe17, після PR #51. Мета цільового `/portfolio/`: LCP <1000 мс, Speed Index ≤1000 мс, Agentic Browsing 5/5. Три попередні публічні мобільні PSI-прогони дали LCP 1201/929/1201 мс і SI 961/929/925 мс. Один успішний прогін не підтвердив стабільність.

## Причина та межі доказів

Збережена production-траса 18.10.2026 показала перше компонування 1075 об’єктів протягом 179,304 мс (285,649–464,953 мс після навігації). Обкладинка завершила мережеве завантаження на 396,019 мс, але її callback оброблено на 498,695 мс; малювання відбулося на 547,906 мс. Шрифти завершилися під час цього компонування. Це підстава перевірити зменшення початкової роботи над далекими картками; віднімати 179 мс від симульованого LCP некоректно.

У діагностичній локальній парі `content-visibility:auto` зменшило кількість об’єктів першого layout з 1075 до 201 та обсяг запитів зі 147349 до 107228 байтів. При цьому час layout не покращився (40,541 → 50,640 мс), raw LCP змінився зі 100 до 99 мс, а симульований лишився близько 1352 мс. Це доказ меншого початкового обсягу обробки, а не CPU- або production LCP-виграшу.

На localhost шрифти й зображення завершуються перед першим layout. На CDN вони завершувалися під час нього. Тому локальний результат не доводить ні досягнення цілі, ні відсутності ефекту на CDN. Потрібні повторні публічні PSI після релізу.

## Зміни

- Посилання карток каталогу використовують `content-visibility:auto` лише для екрана. Повний текст і звичайні посилання залишаються в документі; браузер сам розкриває картку біля viewport, під час пошуку або фокуса. Початкова оцінка висоти запам’ятовується після фактичного рендерингу. Навколо картки є запас для видимого клавіатурного фокуса. Для друку обмеження не діє. Обгортка article не отримує containment, щоб посилання залишалися в нативному дереві доступності. `aria-label` генерується з того самого заголовка, що й h3: посилання на пропущений дочірній h3 через `aria-labelledby` давало порожнє доступне ім’я. Перевірка повного AX tree до прокручування охоплює кожну картку, також без JS.
- Inline CSS каталогу генерується зі спільного bundle та об’єднання класів усіх мовних/річних каталогів і контролерів. Аналізатор прибирає тільки неможливі гілки селекторів, зберігає порядок, responsive rules, font-face, змінні й динамічні стани. Невідомі сценарії або помилки повертають повний CSS. Зовнішній bundle залишається повним.
- Шрифти Roboto, їхні контури, накреслення й preload, якість та кадрування фото, банер і логіка згоди, Cloudflare beacon, агентні інструменти та `noindex,nofollow` зберігаються.
- Локальний benchmark-сервер використовує HTTP/1.1 keep-alive замість окремого HTTP/1.0 з’єднання для кожного ресурсу. Це все одно не модель HTTP/3 CDN.

## Відкинуті експерименти

Усі наведені нижче пари — локальні Lighthouse 13.5.0, холодний перший візит із банером, стандартний mobile/Slow 4G simulation. Перші експерименти використовували HTTP/1.0; вони не є production PSI.

| Вбудувати обидва WOFF2 | 1427,6–1438,4 | 1505,3–1578,3 | Відхилено: HTML gzip приблизно 26 → 52 КБ |
| Один variable WOFF2 | 1427,4–1427,6 | 1502,2–1519,3 | Відхилено, попри економію 4,7 КБ |
| Знизити пріоритет обох font preload | 1352,5–1353,1 | 1355,2–1357,0 | Немає користі |
| Прибрати лише Regular preload | 1354,7–1355,5 | 1427,7–1428,5 | Відхилено |
| Прибрати обидва font preload | 1354,3–1354,7 | 1427,8–1428,5 | Відхилено; SI також зріс до 1053 мс |

П’ять пар початкового кандидата (containment на article, до виправлення доступних посилань) й актуального Linux-артефакту `main` через однаковий HTTP/1.1 benchmark дали (мс): baseline: lcp 1351.7–1352.8 (медіана 1352.5), speedIndex 777.3–847.4 (медіана 819.8), tbt 0.0–33.0 (медіана 0.0); candidate: lcp 1351.5–1351.8 (медіана 1351.8), speedIndex 807.7–826.9 (медіана 812.9), tbt 0.0–15.0 (медіана 0.0). CLS=0 і Performance/Accessibility=100 в усіх десяти прогонах. Загальна передача зменшилася зі 147349 до 103727 байтів (29,6%). LCP практично не змінився; ці результати не підтверджують досягнення production-цілі. Розкид і викиди не вилучалися.

Variable-font експеримент додатково перевірено GPT‑6.1: оптимізовані varLib deltas змінювали деякі координати до 0,5 font unit. Незалежно від невеликої похибки, виміряна регресія виключила його з релізу.

## Перевірки та приймання

Збірка перевіряє всі мовні пари, медіа й версії. Браузерна матриця охоплює всі кейси; додатковий маршрут каталогу перевіряє UA/EN на 390/768/1440 px, кожен рік і кожну картку, далекі клавіатурні переходи, фокус, прокручування та друк. Галерея й consent-сценарії залишаються в чинних перевірках.

Після terminal success PR CI, мерджу й Pages перевірити живі версії, потім виконати цільовий Cloudflare purge двох загальних каталогів. Налаштування Cloudflare до мерджу не змінювати. Повторити десять різних URL з `scripts/release-sample.json`, усі головні UA/EN пункти меню та native WebMCP.

Для цілі потрібні п’ять послідовних публічних mobile PSI-прогонів з усіма LCP <1000 мс, SI ≤1000 мс та Agentic Browsing 5/5. Зберегти URL, точні значення й весь діапазон, включно з перевищеннями. Локальний результат або Performance 100 не замінює цього приймання. Звіт після релізу зберігати окремим артефактом і в описі PR; цей документ описує підготовлену зміну, не майбутній досягнутий результат.

Джерела методики: [оптимізація LCP](https://web.dev/articles/optimize-lcp), [content-visibility і доступність](https://web.dev/articles/content-visibility), реалізація Lantern у закріпленому Lighthouse 13.5.0.
